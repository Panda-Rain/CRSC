# 进度计划 · 甘特图 / 网络计划图

面向地铁机电（BAS、门禁、综合监控等）施工交底场景的**纯前端单文件进度计划工具**。
同一份任务数据，可在「进度计划图（甘特图）」与「网络计划图」之间整屏切换。

> **双击 `index.html` 即可使用**，不需要 npm、不需要构建、不需要本地服务器。
> 首次打开需联网（React / Tailwind / html2canvas 等库从 CDN 加载，字体从 Google Fonts 加载）。

## 快速开始

直接双击根目录的 `index.html` 即可。也可以用任意静态服务器打开：

```bash
python -m http.server 8080
# 然后访问 http://127.0.0.1:8080/index.html
```

打开后就是一个可直接编辑的示例项目（地铁车站 BAS / 门禁系统 8 项任务），
日期相对「今天」生成，因此能立刻看到「今天」标记线与真实的进度状态。

## 界面导览

自上而下分三块：顶部标题区、工具栏、主体区。

### 1. 顶部标题区

| 元素 | 说明 |
|---|---|
| 工程名称 | 居中大标题，**点击即可直接改**（单行输入框，自动伸缩） |
| 概览统计 | `共 N 项任务 \| 计划周期 X 天 \| 总完成率 Y% \| 关键工作 Z 项 \| 起止日期` |
| 完成率进度条 | 蓝紫渐变，实时反映整体完成率 |

> 「总完成率」按**工期加权**计算，不是简单求平均，因此长工期任务对结果影响更大。

### 2. 工具栏

从左到右：

| 控件 | 作用 |
|---|---|
| **搜索框** | 实时过滤任务（匹配**任务名称 + 任务内容**），右侧显示 `命中 n/N`，关键词在列表中高亮，带清空按钮 |
| **日 / 周 / 月** | 切换右侧时间轴的刻度密度（仅在进度计划图下显示） |
| **网络计划图** | 整屏切换到网络视图；再次点击切回；蓝色高亮表示当前处于网络视图 |
| **关键路径** | 开 / 关「关键工作」的标红标注（勾选动作本身在「编辑任务」弹窗里完成） |
| **深浅色** | 深色 / 浅色主题切换 |
| **导出** | 下拉菜单，见 [导出](#导出) |
| **新建任务** | 打开空白任务弹窗 |

### 3. 主体区（二选一全屏）

`进度计划图`（默认）或 `网络计划图`。**两者共用同一份 `tasks` 数据，切换不会重置任何内容。**

## 功能清单

### A. 进度计划图（甘特图）

**左侧任务表**

- 列：`序`（拖拽排序柄）｜`任务名称`｜`任务内容`｜`开始`｜`结束`｜`工期`
- **行高 40px、表内文字 12px**（2026-10-11 曾试过放大到 52px / 14px，整屏偏大，已改回）
- **没有「关键」列**（2026-10-12 按要求取消）：主界面不再有勾选框，
  关键工作统一在「**编辑任务**」弹窗里勾「设为关键工作」
- 任务名称列会显示两个标识：关键工作（红点）、里程碑（橙色小旗）——红点即关键工作的状态提示
- **表内文字统一为黑色**（2026-10-12 按要求把 `任务名称 / 任务内容 / 开始 / 结束 / 工期` 全部改黑，深色主题下为浅色）；
  只有「序」号列和表头仍保持灰色，里程碑在「工期」列的「节点」二字保留琥珀色
- **每一列的右边界都可拖拽调宽**；鼠标移到列头缝隙出现拖拽柄
- **整个任务表宽度可拖拽**（左侧分隔条），双击复位到 584px
- **行可拖拽排序**：抓住「序」号拖动到目标行即可换位
- 底部有「**+ 新建任务**」行，点击打开新建弹窗
- **右键菜单**：编辑任务 / 上移一行 / 下移一行 / 删除任务

**右侧时间轴**

- 两行表头：
  - 上排 = 分组行（日 / 周视图按**月**分组，月视图按**年**分组）
  - 下排 = 刻度格，**每一格都带完整时间文字**
- 网格：竖格线、周末底色、**完整外框**（最下横线与左侧最后一行任务的下边框严格对齐，右侧竖线与时间轴右端对齐）
- **今天高亮列** + 顶部「今天」小徽标
- 任务条：**百分比画在进度条「里面」的左端（贴条左端内侧 6px）+ 任务名称挂在进度条「后面」（右外侧 8px）**，
  整行读作 `[100% ███░░]　任务名称`；里程碑渲染为**菱形节点**，名称留在菱形右侧
  - 百分比 11px、**位置固定在条左端内侧、不随进度移动**，只有**颜色会翻转**：
    填充盖住这块标签区 → **白字**（衬在深色填充上），没盖住 → **深字**（衬在浅色未填充底上），
    所以任何进度下都看得清
  - **条太窄（宽 < 34px）时整块不显示百分比**，避免被条的圆角/边界裁成半截数字（月视图缩到最小时才有这种情况）
  - 名称 11px、**黑色**（深色主题为浅灰）；关键工作的**名称标红**（深色主题为浅红），
    条内百分比不跟关键色走
  - 文字层 `pointer-events: none`，不挡任务条的拖拽与两端改期
  - 进度条高 30px（行高 40px 内居中，上下各留 5px 净空），圆角 6px
  - 里程碑菱形 18px，名称字号 11px
  - ⚠️ 任务条贴到时间轴最右端时，右侧文字会被时间轴边界裁掉属于正常现象（可横向滚动查看）
- 依赖连线：**保留连线本身、但不画箭头**（箭头只在网络计划图里出现）
  - **非关键线路为黑色虚线**（`5 3`、1.4px）、**关键线路为红色实线**（`#dc2626`、2px）
  - 连线一律从**紧前任务的右端**出发、走到**紧后任务的左端**收住，按间隔分两种走线：
    | 情况 | 走线 |
    | --- | --- |
    | 间隔 ≥ 0（含**紧后次日开工**的 0 间隔） | 一条**平滑 S 曲线**直达紧后任务左端 |
    | 间隔 < 0（**下面任务的开始时间在上面任务前面**） | **曲线绕道**：从紧前条右端伸出 → 拐到两行之间的净空走廊 → 向左绕到进度条**前端（左端）之前** → 再拐回来接入左端 |
  - S 曲线的控制点横向外扩量 = `max(20px, 间隔/2)`、上限 64px。
    下限 20px 是关键：**间隔为 0（截图里那种"下面开始日 = 上面结束次日"）时它保证线依然是一段柔和的曲线**，
    不会退化成一根竖直直杠或生硬的直角折线
  - S 曲线横向最大偏移只有控制点的约 0.29 倍（0 间隔时约 5.8px），且向右的鼓包落在紧前条右缘之外、
    向左的鼓包落在紧后条左缘之外，所以**曲线全程在两条任务条之间的空白里摆动，不会压到任务条**
  - 绕道的横向走廊取在紧后任务所在行的**行边界**上：任务条占行内 `top+5 ~ top+(行高-5)`，行边界上下各有 5px 净空，所以走廊不会压到任何任务条；同一个任务有多个紧前工作时，各条线在走廊里上下错开 3px 避免重叠
  - 深色主题下纯黑连线看不见，故非关键线自动转为浅灰
  - 连图层 `pointer-events: none`，不影响任务条的拖拽与两端改期
- **悬停联动**：鼠标移到左侧某一行，右侧对应任务条同步高亮（反之亦然）
- 拖拽改期：**中间**整体移动，**左右两端**调整起止日期
  （两端手柄在鼠标悬停时出现；时间轴太密或任务条过窄时会自动隐藏，避免误触）
- 任务条 tooltip：任务名称 / 任务内容 / 起止日期与工期 / 进度 / 是否关键工作

**滚动同步**：四路联动 —— 左表头↔左行、右表头↔右图体、左行↔右图体（横向 + 纵向）。

**时间轴缩放滑块**（右下角悬浮胶囊）

- `缩小 ─── 滑块 ─── 放大 | 150% | 重置`
- 范围 **40% ~ 300%**，实时缩放整条时间轴（刻度格、任务条、依赖连线、今天线全部同步）
- 缩放时**锁定视口中点**，画面不会跑到别处
- 切换 日 / 周 / 月 时倍率**自动复位到 100%**
- 该控件位于导出区域之外，**不会出现在导出的图片里**

### B. 网络计划图

- 整屏替换进度计划图，数据完全同步
- 节点内容：**任务名称** + 起止日期 + 进度条与百分比 + 工期 / 前置后置数量 + 关键标记
  （节点内**不显示任务内容**，任务名称最多 3 行）
- 依赖连线：连线**收在箭头尾部**，箭尖刚好落在下游节点的左边缘上（不会直接连到任务块）
  - **配色**：非关键线路为**黑色**、关键线路为**红色**（`#dc2626`），
    箭头与连线同色（`fill="currentColor"`，跟随同一个 `<svg>` 的文字色）
  - 深色主题下纯黑连线在深底上看不见，故非关键线自动转为浅灰；
    关键线的红色在深浅主题下都保留
  - 箭头为固定 `12 × 8`（`markerUnits="userSpaceOnUse"`），**不随线宽缩放**，
    因此关键线（2.2px 红实线）与普通线（1.5px 黑虚线）的箭头大小完全一致
  - 普通依赖为虚线 `6 4` 并带圆头端点，使虚线断口在收口处自动收缩、紧贴箭头尾部
- 工具条：`自动布局` / `适应视图` / `缩小 · 百分比 · 放大` / `重置视图`
- 交互：**双击节点**编辑、**拖动节点**移动、**悬停节点右侧圆点拖到另一节点**建立依赖、
  **空白处拖动**平移画布、**Ctrl（⌘）+ 滚轮**缩放
- 左下角图例：依赖关系 / 关键线路 / 里程碑
- 进入该视图时**自动适应视图**，保证所有节点一进来就在画面内

## 时间轴视图与缩放

三种视图都是**按时间单位切格**（不是单纯按天拉伸），因此每格都有完整文字：

| 视图 | 每格代表 | 格内显示 | 基准密度 |
|---|---|---|---|
| **日** | 1 天 | 日期数字 + 星期简称（如 `9` / `五`） | 40 px / 天 |
| **周** | 1 周（周一起算） | 起止区间 `10/05 ~ 10/11`（格窄时退化为 `10/05`） | 22 px / 天 |
| **月** | 1 个月 | `2026年10月` | 10 px / 天 |

实际密度 = 基准密度 × 滑块倍率（40% ~ 300%）。

> 时间轴在项目起止日期前后各留了少量空白（开工前约 4 天、完工后约 8 天），
> 方便把任务往两头拖。

## 关于「关键工作」

本项目**不内置 CPM 自动计算**（不自动算 ES/EF/LS/LF 与总时差），
关键工作完全由**人工勾选**，入口只有一个：

- 任务编辑弹窗里勾「**设为关键工作**」

> 主界面任务表原有的「关键」复选框列已于 2026-10-12 按要求取消，
> 避免在表里误点；任务名称列的红点仍然表示"这是一项关键工作"。

勾选后，该任务在甘特图与网络图中统一标红（红条 / 红环 / 红色实线连线），
顶部概览同步显示「关键工作 N 项」。
> 这么设计是刻意的：施工现场的「关键线路」往往由交底人依据经验与工期盘子判断，
> 半自动的时差算法一旦与现场认知不一致，反而更容易误导。
> 示例数据中预设了 6 项关键工作（施工准备 → 预埋桥架 → BAS 设备安装 → 单机调试 → 系统联调 → 竣工验收）。

## 导出

点工具栏「导出」：

| 菜单项 | 说明 |
|---|---|
| 进度计划图 → **导出 PNG 长图** | 会自动把内部滚动容器「撑开」后整图截图，**长图不会被裁切** |
| 进度计划图 → **导出 PDF（自动分页）** | A4 **横向**，按页高自动分页，不会把长表压成一页糊掉 |
| 网络计划图 → **导出 PNG** | 若当前不在网络视图，会先自动切换再截图 |

导出区域为 `#gantt-export-area` / `#network-export-area`；
时间轴缩放滑块、网络图工具条等**辅助控件都在导出区域之外**，不会被截进去。

## 技术实现要点

| 项 | 说明 |
|---|---|
| 运行时 | React 18 UMD + ReactDOM 18 UMD（production 版） |
| 编译 | `@babel/standalone` 浏览器端编译 `<script type="text/babel">`，**classic runtime**（输出 `React.createElement`） |
| 样式 | Tailwind CSS（CDN）+ 内联自定义样式，自定义 `notion` 色板；`darkMode: 'class'` |
| 图标 | 内联 SVG 图标组件（`Icons.*`），不依赖图标库 |
| 导出 | html2canvas 1.4.1 + jsPDF 2.5.1 |
| 日期 | **统一本地时区**（`getFullYear / getMonth / getDate`）构造与格式化，禁止 `toISOString()` |

几个关键实现细节：

- **时区安全**：所有日期计算走本地时区，避免东八区下整体差一天。
- **长图导出**：导出前把内部滚动容器改为 `overflow: visible` 并按 `scrollWidth / scrollHeight`
  自底向上撑开，再用整体外框尺寸截图，导出后还原。
- **网格高度约束**：区分 `gridHeight`（= 任务行数 × 行高，网格与今天列只画到这里）
  与 `contentHeight`（= 网格 + 一行「新建任务」），保证右侧竖格线不会超出左侧任务行数。
- **状态提升**：`sidebarWidth` / `colWidths` 保存在应用层，因此切换到网络图再切回来，调好的列宽不会丢。
- **条件渲染**：两个视图互斥挂载（而非 `display:none` 隐藏），因为隐藏元素尺寸为 0、无法截图。
- **反馈机制**：操作提示统一走轻量 Toast，危险操作走自定义确认弹窗，不使用原生 `alert` / `confirm`。

> 因此：**维护时只改 `index.html`**。若今后要走 `npm + Vite` 工程化路线，

## 已知限制

## 本地校验

改动 `index.html` 后，可以在**没有浏览器**的环境里做一次「语法编译 + 真实 React 挂载」自检，
用来兜住 Babel 语法错误、运行时报错、以及交互逻辑回归。

思路（本仓库不附带校验脚本，需要时按下面几行自己搭）：

1. 抽取 `index.html` 中 `<script type="text/babel">` 的内容；
2. 用 `@babel/standalone` 按 **classic runtime** 编译：
   `Babel.transform(code, { presets: [['react', { runtime: 'classic' }]] })`；
3. 在 `jsdom` 里先后 `window.eval` React UMD、ReactDOM UMD、上一步的编译产物；
4. 用 `dispatchEvent` 派发真实的 `mousedown / mousemove / mouseup / input / click` 事件，
   再断言 DOM（行数、样式高度、勾选状态、文字内容等）。

```bash
npm install jsdom
node verify.mjs        # 你自己按上述思路写的校验脚本
```

> 关键陷阱：`@babel/standalone` 对 `text/babel` 默认使用 **classic runtime**
> （输出 `React.createElement`），因此校验时也必须用 classic，否则会因找不到
> `react/jsx-runtime` 而直接白屏。
